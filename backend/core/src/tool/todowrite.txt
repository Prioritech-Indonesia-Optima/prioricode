Create and maintain the session todo list — the user's live view of your progress and the plan in force. Any request that modifies files or spans multiple steps requires a todo list, seeded BEFORE the first change. The list is persisted outside the conversation (it survives compaction and restarts) and every response echoes the live list, so you never re-emit it.

Treat the list as sacred: mutate it IN PLACE, never rebuild it from memory. Address items by the (td_…) id shown in every response — the live list always wins over your recollection; when in doubt, "view" first.

Actions:
- "view" — read the live list; changes nothing.
- "add" — append items [{content, priority?, phase?, after?}]; after="<id>" inserts behind that item.
- "status" — check items: batch [{id, status}] in ONE call (completing the current task and starting the next is one transition; the list must hold at most one in_progress, and none once work is finished).
- "edit" — reword items [{id, content?, phase?, priority?}]; phase:"" clears the label.
- "remove" — drop items by id when scope changes (set status "cancelled" instead when the user should see the drop).
- "replace" — a complete list, ONLY to seed the first todo of a new objective or a user-approved pivot. While unfinished tasks exist the call is rejected once with their exact ids; resubmit only with `confirm` listing exactly those ids. Never rebuild out of habit.

Discipline (every one is mandatory):
- Cross off — "status" to completed — the instant a task is truly done and verified. Never batched, never on intent.
- Capture new instructions as todos immediately; append discovered follow-ups; remove or cancel dropped scope.
- Structure: group work into phases — consecutive tasks sharing a `phase` label render as one collapsible group ("Phase 1: schema", "Phase 2: wiring"). Open a phase by adding its first task with that label; finish a phase's tasks before starting the next.
- Never end a modifying turn with unfinished tasks unless the user stopped you.
- Preserve user-provided commands verbatim (flags, args, order); items specific and actionable.

Skip only for: a single trivial edit, or purely informational questions. When in doubt, write the list.
