## Workflow

### Phase 1: Explore
Launch up to 3 explore agents in parallel to understand the codebase.
Focus: relevant files, patterns, tests, dependencies.
Use 1 agent for isolated tasks, up to 3 for complex multi-area work.

### Phase 2: Brainstorm
Launch 2-3 general subagents IN PARALLEL with different perspectives to design the approach.

**Perspectives by task type (choose 2-3 that apply):**
- Modification: minimal-diff / clean-architecture / risk-averse
- Creation: simplest-viable / extensible / performance-first
- Fix: root-cause / pragmatic-patch / prevention
- Always include: risk/edge-case hunter (what breaks, blast radius)

**Skip subagents** only for truly trivial tasks (typo fixes, single-line changes).

Synthesize their outputs. Pick the best path. Note your rationale in the plan file.

Do NOT ask for approval. Proceed directly to execution.

### Phase 4: Execute
Follow the plan phase by phase:
1. Create a todo list with one item per plan phase. All items start as `pending`.
2. Before starting a phase, mark its todo as `in_progress`.
3. Execute the phase. Run its verification command.
4. Once verification passes, immediately mark the todo as `completed`, then auto-commit ("auto: <phase name>").
5. If verification fails: diagnose, fix, re-verify. Max 3 retry attempts per phase.
6. If a phase fails after 3 attempts: keep the todo `in_progress`, add a follow-up todo describing the blocker, continue to next phase if independent.
7. Do not add scope beyond the plan. If you discover something that needs fixing but isn't in the plan, note it in the final report.

**Todo discipline (live progress):**
- Exactly one todo in `in_progress` at a time.
- Mark `completed` the moment verification passes — do not batch completions.
- Never mark a todo `completed` without having run its verification command.
- The todo list is the user's live view of progress. Update it in real time.

### Phase 5: Final Verification
Run the end-to-end verification from the plan:
- bun run lint
- bun run typecheck
- Any project-specific test commands from the plan
- If failures: fix and re-run (max 3 attempts)

### Phase 6: Report
